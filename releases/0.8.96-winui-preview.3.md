# FClash 0.8.96 WinUI preview.3

This is a local Windows migration preview, not a replacement for the published 0.8.96 release or tag.

## Features

- Restore the Flutter presentation contract: compact 80 px icon rail with optional labels below icons, original Material icons/Roboto, exported Material You colors and compact page headers.
- Restore the dashboard's responsive masonry grid, original default card order, speed curve, usage donut, radio outbound modes and lower-right start/stop action. Keep existing dashboard customization and drag ordering.
- Restore Tools → Advanced → DNS/additional rules, ordered-list subpages, parent back navigation and scroll position. Configuration rows open editors; add/edit actions stay in the toolbar.
- Restore profile radio cards/context menus, update/reorder toolbar, import floating action, proxy group tabs, search/options toolbar and delay-test floating action. Column density follows the Flutter calculations.
- Present backup and hotkey settings as compact lists with editors. Keep cached proxy flags and their manual-test update policy.

## Bug Fixes

- Remove the first preview's oversized sidebar, footer settings/start buttons, default memory/profile cards and multi-address local-IP wall.
- Separate dashboard option-card clicks from direct switch changes.
- Preserve logical window dimensions at different monitor DPI values without shrinking the window at each launch.
- Publish compiled XAML and the application PRI index alongside the executable; fail packaging if required XAML/font/palette resources are absent. This fixes the startup failure caught while checking the first rebuilt preview package.
- Expose ordered-list title/detail properties to WinUI runtime binding.
- Restore the WebDAV entry under backup and restore.

## Validation and limitations

See [native validation](../windows-native/validation.md). This preview makes no measured production-memory improvement claim. Native text rasterization, focus indicators and popup animations may differ from Flutter. Proxy/TUN/elevated lifecycle checks require a dedicated test machine; host verification uses isolated safe-mode data only. Global script-library/editor parity and translation completeness remain migration work; the current per-profile script editor is still provided.
